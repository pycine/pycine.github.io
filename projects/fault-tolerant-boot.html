01Overview

Assume the first boot will fail.

This project makes a Yocto device recover from a broken boot without a technician. U-Boot tracks boot attempts, and after repeated failures it falls back from the primary image to a minimal recovery system.

Detection is only half the problem. The flow also needs a userspace success signal, so a kernel that starts but never reaches a healthy system is still treated as a failure. The recovery behavior was validated in QEMU ARM64.

02Build

What I built

  • Designed a fault-tolerant boot flow using U-Boot with an automatic fallback path.
  • Implemented boot-attempt tracking that survives across failed boots.
  • Added Linux userspace success confirmation so a partial boot cannot clear the attempt counter.
  • Built a minimal recovery image that takes over after the failure threshold.
  • Used FIT signatures to protect the images selected by the bootloader.
  • Validated the recovery behavior in QEMU ARM64.
03Architecture

The fallback sequence

01

Boot

U-Boot starts and increments the persistent boot counter.

02

Try

The primary Yocto image is selected and starts booting.

03

Confirm

Linux userspace must report a healthy system before the counter is cleared.

04

Fallback

If success never arrives, the counter reaches its threshold and U-Boot switches to the recovery image.

05

Recover

The minimal image comes up with a known-good environment for repair.

04Highlights

Technical highlights

Recovery by default

A device that cannot reach userspace still has a path back to a working system.

Bootcount tracking

Failed attempts are persisted across resets, so a reboot loop cannot hide the failure.

Userspace handshake

A successful kernel load is not enough — the boot only counts as healthy once userspace confirms it.

Signed images

FIT signatures keep the fallback path from becoming a way to boot an untrusted image.
