01Overview

Eyes and flight control, split across two brains.

SeaDrone is an autonomous maritime drone designed to detect people in distress and support rescue operations. The design splits hard real-time flight control from computationally heavy vision, so neither workload compromises the other.

An ESP32 handles the flight loop and the long-range LoRa link, while a Raspberry Pi 4 runs YOLOv8n over the camera feed and exposes detections through a FastAPI service. Inference happens on board, which matters when the network is the first thing to disappear offshore.

02Build

What I built

  • Built custom flight-control firmware for an ESP32 airframe, including a PID stabilization loop.
  • Deployed YOLOv8n on a Raspberry Pi 4 to detect people in distress from the live camera feed.
  • Built the vision pipeline with OpenCV and exposed detections through a FastAPI endpoint.
  • Added long-range telemetry and command over LoRa for operation beyond Wi-Fi range.
  • Split real-time control and vision across two compute domains on the aircraft.

04Highlights

Technical highlights

Real-time vs. throughput

The flight loop stays on the MCU while vision runs on Linux. Separate timing budgets, separate failure domains.

On-board inference

YOLOv8n runs on the Raspberry Pi, so detection does not depend on a cloud connection.

Long-range link

LoRa provides a command and telemetry path well beyond the range of Wi-Fi.

Custom control

The ESP32 flight controller is purpose-built for the airframe instead of borrowed from a canned flight stack.
